# Step 6 - Write rubric

## What's a rubric?

The Rubric

The complete set of instructions and standards for a perfect result. It ensures every grader treats every response exactly the same.

## The key components

The Criterion

A simple, declarative statement describing a single requirement that can be evaluated as True or False for any given response.

Weights

Numeric values assigned to each criterion that represent the relative importance of that requirement.

## What you'll write in this project

20 to 35 criteria per rubric

In this project, you'll write 20 to 35 criteria for each rubric. Every criterion has 3 fields:

* **Criterion text** - one declarative statement of what's being checked.
* **Weight** - an integer between -100 and +100. **No zero weights.**
* **Rationale** - one sentence explaining why this criterion exists.

# 1. Write the criteria

In this step, you will draft formal criteria. This means moving past your notes and writing a standalone "statement of fact" that any grader can verify without guesswork.

## The 4 principles

Every criterion must pass **4 principles**. These are non-negotiable. Click each card to see how to audit it.

Atomic

### Atomic

Does it check exactly one thing?

Avoid "and" or "also." If a rule has two parts, split it into two criteria.

Self-Contained

### Self-Contained

Does it make sense on its own without additional context?

Avoid saying "as mentioned above" or "refer to the prompt".

Objective

### Objective

Are the "vibe words" (helpful, good, clear) removed?

Use numbers or binary facts that two different people can't argue about.

Verifiable

### Verifiable

Is there clear evidence in the response?

There must be evidence in the AI response to prove the rule was met. If you can't point to it, you can't grade it.

## Examples

Review the examples below to see how the decomposed **prompt** and **deliverable** from previous steps evolve into high-quality **rubric criteria**.

"Example 1 — The Request"

**Prompt:** "Create a 5k exercise program"

**Criterion:** The model response provides a weekly exercise schedule that culminates in a 5k run or race.

"Example 2 — The Constraint"

**Prompt:** "Include the location"

**Criterion:** The model response specifies workout locations that are physically located within the South Brooklyn area (e.g., Downtown Brooklyn, Park Slope, or Brooklyn Heights).

"Example 3 — The Constraint"

**Prompt:** "5 days per week"

**Criterion:** The model assigns exactly five days of exercise and two rest days per week.

* **Process words are banned:** calculates, computes, derives, determines, figures out.
* **Mind-reading words are banned:** considered, understood, took into account, analyzed, evaluated, recognized, accounted for.

# Weighting principles

Required minimums

* At least **1 Critical-tier positive** (the headline finding).
* At least **1 Deal-breaker negative** (the worst thing the model could do for this user).
* With 20-35 criteria total, only **2-3 should land in Critical**.
* An all-positive rubric can only catch what the model missed, not what it did wrong.

## Three principles of weighting

### 1. All weighting is relative

Weights don't exist in a vacuum - they function as a **priority map**. A "+80" item is only critical if the rest of the rubric isn't also filled with +80s. *If everything is a priority, nothing is.*

Pro tip - use a fixed budget

With 20-35 criteria in a rubric, only **2-3 should land in the Critical tier** (+60 to +100). If you've tagged six criteria Critical, you haven't prioritized - you've flattened.

### 2. Must-haves vs. nice-to-haves

Sort every criterion into a tier **before** you touch a weight. The tier tells you the range; you fine-tune within it.

#### Positive weights (criterion met = points awarded)

| Positive weighting | Examples |
| --- | --- |
| **Critical / Must-have (+60 to +100)** | If the model fails this, the entire response is useless. e.g., the user asked for a 5K training plan and the model returned a cake recipe. |
| **Important (+25 to +55)** | The response is still usable, but significantly degraded. e.g., the plan is there, but it's built for an advanced runner instead of the beginner the user described. |
| **Minor / Nice-to-have (+5 to +20)** | Polishing touches that don't affect fundamental correctness. e.g., a specific formatting request like "use bold text for exercise names." |

### 3. Negative weighting (the deal-breakers)

Sometimes, doing something wrong is worse than forgetting to do something right.

Use negative weights for **constraint violations, hallucinations, regulated-advice overreach, and material math errors**. If the model gives dangerous financial advice, it shouldn't just score 0 on the positive criterion - it should be penalized to the bottom of the pile.

Model omits something

You wrote a positive criterion for it. The model didn't deliver. **The zero is the penalty.** Absence is already handled.

0 pts

**Don't write a mirrored negative.** If 'Identifies avalanche method' is +80, adding 'Fails to identify avalanche method' at -80 penalizes the same miss twice - once through the 0, once through the negative.

✓ No negative weight needed

Model does something wrong

The model committed an act the user didn't ask for - or was told not to do. A zero isn't enough. **A negative weight actively separates this response** from one that simply omitted the item.

-60 pts

⚠ Use a negative weight here

#### Negative weights (criterion triggered = points subtracted)

| Negative Weighting | Examples |
| --- | --- |
| **Deal-breaker (-60 to -100)** | Hallucination, regulated-advice overreach, explicit constraint violation. |
| **Significant (-30 to -55)** | Real harm but recoverable (wrong tax rate, missed secondary constraint). |
| **Minor (-5 to -25)** | Sloppy but not catastrophic (hedge words, missing context line). |

#### Negative Weights Examples

| Points | Example | Category |
| --- | --- | --- |
| **-70** | Model recommends opening a balance transfer card after user explicitly said no balance transfers. | Constraint violation |
| **-80** | Model cites a 2026 NIIT income threshold that doesn't exist in the tax code. | Hallucination |
| **-70** | Model recommends a specific index fund when the prompt was about debt payoff, not investing. | Regulated-advice overreach |
| **-60** | Model double-counts a mortgage payment to make available cash flow look higher than it is. | Material math error |

Trap to avoid - double counting

If a model misses something the user asked for, the positive criterion already fails and awards 0 points. That 0 is the penalty, so you don't need a negative weight on top of it.

For example: you ask for an itemized budget. The model doesn't itemize. The positive criterion for itemization fails. Done, no extra deduction needed.

So don't write a negative criterion that just mirrors a positive one. If "Response identifies cash advances as a category" is worth +30, don't also add "Response fails to identify cash advances" at -30. That's double-counting the same miss.

Save negative weights for things the model actively did wrong - behavior the user never asked for and didn't want, not things it simply left out.

# Weighting guide

The rubric should have a **clear pyramid**: many minor criteria, fewer important, very few critical.

Same shape on the negative side.

### Scoring guidance

| Category | Item | Points | Notes |
| --- | --- | --- | --- |
| Reasoning | Main findings | 80-100 | The headline conclusion of the response. |
| Reasoning | Major reasoning steps | 60-80 | Intermediate logic that drives the main finding. |
| Reasoning | Minor reasoning steps | 30-60 | Supporting logic that shapes part of the answer. |
| Extraction | Major extracted number or information | 60-80 | Affects the overall calculation or main conclusion. |
| Extraction | Minor extracted number or information | 30-60 | Affects only part of the calculation or conclusion. |
| Extraction | Very minor extracted number or information | 10-30 | Not major or minor, but still improves quality or completeness. |
| Instruction following | Major instruction | 40-60 | Affects the main calculation or conclusion (e.g., using a specific methodology). |
| Instruction following | Minor instruction | 20-40 | Does not affect the main calculation or conclusion (e.g., avoiding a recommendation for online apps). |
| Formatting | All formatting items combined | up to 50 total | Divide across all formatting requirements: response sections, monetary values, percentages, or any other required presentation format. |

### Quick calibration check

Before you save a weight, run it against these sanity checks. Most miscalibrated rubrics come from skipping them.

### Pyramid check - is the shape right? Your highest-weighted positive (+60 to +100) should be the headline finding, not a formatting requirement. If your top positive is "Response uses dollar formatting," reweight. No more than 2-3 criteria should land in the Critical (+60 to +100) tier. Six Criticals -> dilute most to Important (+25 to +55). Your largest negative (-60 to -100) should be the worst real-world failure for this user: violated constraint, hallucinated rule, regulated-advice overreach.

### Severity check - does the weight match the harm? A formatting or polish criterion at +50 or higher is almost always wrong. Polish doesn't carry that much weight. A safety, hallucination, or constraint-violation criterion at -5 or -10 is almost always wrong. These are the worst things the model can do - weight them accordingly. A minor sub-calculation at +60 is almost always wrong. Sub-calculations are Important (+25 to +55), not Critical.

### The partial-credit smell test If you find yourself thinking "this criterion should be worth half credit if the model partially got it," the criterion needs to be split into two atomic criteria, not weighted differently. PASS/FAIL is binary by design.

### The "would I trade" test Look at your two highest-weighted positives. If a model gave you criterion A but not criterion B (or vice versa), is the response with A clearly more useful to the user than the one with B? If you can't tell, the weights are too close. Spread them.

# Audit your rubric

## What the rubric should cover

The rubric as a whole should cover all 4 failure axes: **Instruction Following, Reasoning, Extraction, Formatting**. You do not need to tag each criterion with one of these, but when you do the full-rubric audit at the end, scan and make sure every axis is represented.

## Check each criterion

Before finalizing your rubric, run every individual criterion through this 4-point audit to ensure it is "pro-grade."

Run every criterion through these four checks.

### Check Each Criterion

0 of 4 complete

**The Self-Containment Check** - Can a grader who has never seen the prompt use this criterion to judge the response?Look for references like "as requested," "the user's schedule," or "the prompt." Fix - replace references with hard facts, such as "9:00 AM - 9:00 PM."**The Specificity Check (Avoiding "Overfitting")** - Is your criterion so narrow that it only allows one "correct" version of the response?Look for demands of a specific word choice or one exact option when multiple valid options exist. Fix - broaden the "how" while keeping the "what."**The Objectivity Check** - Is there any room for a grader's personal opinion or "vibe"?Look for subjective adjectives like "helpful," "appropriate," "easy," or "beginner-friendly." Fix - use binary, verifiable facts like "lists specific exercises."**The Weighting Check** - Does the point value assigned to this criterion reflect its true impact on the user's goal?Look for "minor" formatting rules having the same weight as "critical" content. Fix - ensure the core request represents the majority of the total possible score.

## Check the full rubric

A collection of "perfect" criteria can still result in a "bad" rubric if they overlap, leave gaps, or are impossible to grade. Use these five checks to audit the entire system.

Audit the rubric as a whole against these five checks.

### Check the Full Rubric

0 of 5 complete

**The Redundancy Check** - Multiple criteria that penalize the model for the same mistake ("Double Jeopardy").Example - one criterion for "Correct Grammar" and another for "Professional Tone." If the AI uses slang, it fails both, which artificially tanks the score. Fix - merge overlapping rules into one comprehensive "Language & Style" category.**The Comprehensiveness Check** - Leaving "blind spots" where the AI could provide a bad response that technically passes every rule.Example - your rubric checks for the 5k plan and the location, but forgets to check if the plan is actually for a beginner. Fix - ask "If a model passes every single one of these, could the output still be useless?"**The Imbalanced Weighting Check** - Small details (like bolding text) carrying the same mathematical weight as the core request.Example - in a 100-point rubric, "Formatting" is worth 50 points and "Exercise Science" is worth 50 points. Fix - ensure your must-haves represent the vast majority of the total score.**The Prompt-Match Check** - Including "ghost criteria" - rules that you think are good, but the user never actually asked for.Example - penalizing the AI for not including "Healthy Meal Prep" when the user only asked for a "5k Exercise Plan." Fix - if it wasn't in the prompt, it shouldn't be in the rubric.**The Deliverable-Match Check** - The rubric is disconnected from the reality of the ideal deliverable.Example - your rubric asks for "3 sets of 10 squats," but your ideal deliverable shows "2 to 3 sets." Fix - ensure your criteria reflect the exact constraints and examples in your "gold standard" output.

If either bar fails, iterate

A prompt that does not break models is not doing its job. If the difficulty or discrimination bar fails, **iterate on the prompt and re-roll** before submitting. Do not adjust the rubric to make the numbers work.

# Rubric examples

Scenario for all 6 examples: a user with $14K in credit card debt across 3 cards asked for a payoff plan that gets them debt-free in 18 months without using a balance transfer.

## 3 Good examples

Good - Headline finding (+80)

**Criterion:** Response identifies the avalanche method (paying highest-APR card first) as the mathematically optimal payoff order given the user's three APRs.

**Weight:** +80

**Rationale:** This is the headline finding. The entire prompt is "what order do I pay these off in?" - if the model gets this wrong, the response fails the user's actual goal.

Good - Required sub-calculation (+45)

**Criterion:** Response calculates a required monthly payment of $850 (+/- 5%) to clear $14K in 18 months at the user's blended APR.

**Weight:** +45

**Rationale:** The 18-month deadline is an explicit user constraint. Without the monthly number, the user can't act on the plan. Important but not the headline.

Good - Constraint-violation deal-breaker (-70)

**Criterion:** Response recommends a balance transfer, debt consolidation loan, or new credit product.

**Weight:** -70

**Rationale:** The user explicitly ruled out balance transfers. Recommending one (or an adjacent product) is a direct constraint violation and a deal-breaker for trust.

## 3 Bad examples

Bad - Vibe words, non-atomic (+50)

**Criterion:** Response is helpful, clear, and addresses the user's debt situation thoughtfully.

**Weight:** +50

**Rationale:** Captures overall quality.

**Why it's bad:** Vibe words ("helpful," "clear," "thoughtfully") - two graders will disagree. Fails Objectivity. Also not atomic: bundles three separate things into one row.

Bad - Formatting weighted as Critical (+60)

**Criterion:** Response uses bold headers, bullet points, and a markdown table for the payoff schedule.

**Weight:** +60

**Rationale:** Formatting makes the plan easier to scan.

**Why it's bad:** Formatting weighted at Critical tier (+60) outranks core correctness. Fails the Weighting Check and the Imbalanced Weighting audit. Also stacks three formatting requirements into one row (fails Atomic).

Bad - Mirror negative, double-counts (-80)

**Criterion:** Response fails to identify the avalanche method as the optimal payoff order.

**Weight:** -80

**Rationale:** Penalize the model when it gets the headline wrong.

**Why it's bad:** Mirror negative of the +80 positive criterion above. Double-counts the same fact. Fails the Redundancy Check. The 0 points from the failed positive is already the penalty.
